# 요청서 규칙 — 하위 저장소(backend · frontend)에 보내는 수정 요청

deskless 는 `backend/` · `frontend/` 를 고치지 않는다(받기 전용). 쿠버네티스로 엮으려고 하위 저장소를 바꿔야 하면 요청서를 쓰고, 그 저장소의 세션이 반영한다(사용자 결정 2026-11-23). 지금 형식의 실제 예: [requests/backend/2026-11-23-k8s-cleanup.md](../requests/backend/2026-11-23-k8s-cleanup.md) · [requests/frontend/2026-11-23-k8s-cleanup.md](../requests/frontend/2026-11-23-k8s-cleanup.md).

## 위치 · 목록

- 요청서: `requests/<backend|frontend>/<YYYY-MM-DD>-<기능>.md`
- 목록: [requests/README.md](../requests/README.md) 의 표(날짜 · 받는 곳 · 요청 · 상태)에 한 줄, 여러 요청을 함께 보내면 "<날짜> 묶음 — 반영 순서" 절(어느 저장소부터 · 동시에 해도 되는지 · 반영 뒤 deskless 가 할 일)

## 형식

```md
# <받는 곳> 요청 — <요청 이름>

- 보낸 곳: deskless (<날짜>)
- 받는 곳: [<저장소>](<GitHub 주소>)
- 기준 커밋: `<hash>` — 지우는 파일의 원본이 남는 커밋(deskless 가 여기서 옮겨 간다)
- 공개 API · 사용자 동작(화면) 변화: 있음 / 없음

## 왜
<왜 바꾸는지>
### 정해진 것 (사용자 결정 <날짜>)
- <결정> …

## 1. 지우는 것        — 대상 | 옮겨 가는 곳 (deskless)
## 2. 더하는 것        — 계약(표) · 구현 메모(근거 `경로:줄`)
## 3. 고치는 것        — 파일 | 고칠 것
## 4. 그대로 두는 것
## 5. 영향 전수 확인 · 정리 (이 요청에 포함)
## 6. 끝난 상태         — `- [ ]` 체크리스트
```

- 근거는 `경로:줄` 로 적는다 — 받는 세션이 바로 찾아가게.
- 공개 API · 화면 변화가 없으면 "없음" 과 이유를 적는다(백엔드 → 프론트 수정 요청 문서 대상인지 판단용).

## 영향 전수 확인 · 정리 (모든 요청서에 넣는다 — 사용자 결정 2026-11-23)

1 ~ 3절 목록은 출발점일 뿐이다. 그 변경으로 **사실이 바뀌는 코드 · 주석 · 문서 · 규약 · 메모리를 받는 세션이 모두 찾아 고치게** 한다. 5절에 넣는 것:

| 항목 | 내용 |
|---|---|
| 찾는 법 | 검색 명령 — `git grep -n -I -E '<검색어>' -- . ':!.beaver/output' ':!package-lock.json'`(지난 기록 · 잠금 파일 제외). 나온 줄마다 고침 · 지움 · 그대로(이유) |
| 범위 | 코드 주석 · 상수 설명 · `AGENTS.md`(주의사항 · 구조 · 각 절 · 체크리스트) · `README.md` · `docs/**` · `.env.example` · `package.json` · 스크립트 · 테스트 · `Dockerfile` 주석 · `.beaver/memory/` · 작업 세션의 Claude 프로젝트 메모리 |
| 규약 맞추기 | 바뀐 전제를 깔고 있는 규칙은 지우거나 새 기준으로 바꾸고, 고친 규칙끼리 어긋나지 않는지 `AGENTS.md` · `docs/` 를 다시 읽는다 |
| 그대로 두는 것 | 지난 기획 · 보고 기록(`.beaver/output/` · 받은 요청서) 등 — 남기는 이유와 함께 |
| 보고 | 커밋 전에 다시 검색해 남은 줄 · 그대로 둔 이유를 요약해 deskless 에 전달 |
| 미리 찾은 곳 | **요청서를 쓸 때 deskless 가 하위 저장소 작업 폴더(`C:\workspace\deskless-backend` 등)를 미리 검색**해 1 ~ 3절에 없던 위치를 표(위치 · 지금 · 고칠 방향)로 적는다 |

6절(끝난 상태)에 "5절 검색 결과가 모두 고쳐졌거나 그대로 둔 이유가 있고, 규약끼리 어긋나지 않는다 — 결과 요약을 deskless 에 전달" 한 줄.

## 받는 곳 · 반영

- **backend** — `changes/<YYYY-MM-DD>-<기능>.md` 로 받아 위에서부터 반영하고, `changes/README.md` 목록에 반영 상태(커밋) · 결과 요약을 적는다(`backend/AGENTS.md:18`). 반영한 요청서는 기록으로 남는다.
- **frontend** — `frontend/changes/` 에 받는다(백엔드 → 프론트 수정 요청과 같은 폴더 — frontend `7dd9da9`).
- 받는 세션은 deskless 파일을 고치지 않는다 — 상태는 deskless 가 고친다.
- 세션에 넘기는 말(예): `<요청서 경로> 요청서를 반영해줘. 5절 영향 전수 확인까지 하고, 끝나면 결과 요약을 알려줘.` 서로 닿는 파일이 없으면 backend · frontend 를 동시에 돌려도 된다.

## 상태 갱신 (deskless)

1. 결과 요약을 받으면 `requests/README.md` 의 상태를 `반영 \`<커밋>\` — 결과 요약: <위치>` 로 고친다.
2. `git submodule update --remote` 로 반영된 커밋을 받는다.
3. 한 커밋으로 — `-요청서 N개 반영 표시(…)` · `-backend · frontend 최신 반영`.

## 기준 커밋

- 지우는 파일의 원본을 deskless 가 옮겨 올 커밋. 요청서를 보낸 뒤 반영 전에 하위 저장소가 그 파일을 또 바꾸면 기준 커밋을 그 커밋으로 고친다 — 2026-11-23 대시보드 재설계로 `d71623e` → `3125886`.
